# ASCEND UX Redesign — Information Architecture (Phase 3)

> **Status:** Decision document. Grounded in the Phase 0 baseline audit and the Phase 1 personas, debated in Phase 2. No app code changes in this phase. Classification: P0 = critical (essential flow or data protection), P1 = primary (frequent, high-value, immediately discoverable), P2 = supporting (belongs in its section, need not dominate), P3 = advanced/infrequent (accessible, not overwhelming the default). Placement values: prominent / in-context / expanded-on-demand / hidden-but-discoverable / consolidated / simplified-visually / proposed-interface-removal (none approved) / proposed-product-removal-requiring-approval (none proposed).
> **Non-negotiables carried from baseline §9:** all capabilities, calculations, data shapes, auth methods, sync behavior, backup/purge/delete, offline-first behavior survive; week = Mon–Sun; Train shows ONLY user plans; the removed 'Ask Coach' drawer stays removed; nothing currently free gets paywalled; no punishing streaks; no fake 'AI' claims; no invented PRs/calories/history; orange/vermilion default; form-check absent from this branch and out of scope.

## 1. Primary navigation — decision

**Five destinations: Today / Train / Progress / Fuel / You.** Mobile: fixed bottom nav (5 tabs, labels always visible — no icon-only tabs). Desktop (≥1024px): left rail with the same five destinations (icons + labels); content column beside it. Below 1024px the rail collapses to the bottom nav. Routes/TabIds do not change (`home | workout | progress | meals | prs | profile | settings`); "You" is a presentation grouping: it lands on Profile with a Profile | Settings segmented control. The Today header gear becomes a shortcut to You → Settings (redirected, not removed); the avatar on every tab opens You → Profile; the notifications bell stays on Today (and opens ReminderCenter).

**Why not four tabs:** the discoverability failure (Top Problem #2, P11 task 11.3) is structural: Profile/Settings/auth are invisible from the nav, and header-icon discovery failed. A labeled persistent destination is the only fix that works from every tab. **Why not more than five:** every additional tab dilutes the four product destinations; nothing else earns a permanent slot (dissent retained in the debate doc: Expert G).

**Tab behavior rules (preserved):** last-tab restore semantics are kept (implementation must preserve `lastActiveTab` behavior, with the open question from P2/P7 — Today-first on training days — tested as a variant, not assumed); tab switches keep the `tab-enter` animation; code-split tabs keep their dynamic imports and `TabSkeleton` fallbacks; `?tab=` / `?sub=` deep links keep working (display labels may change; URL params do not).

**Active-workout behavior:** when a workout is active, the bottom nav/rail shows a persistent "Resume workout" affordance (the active session is never hidden behind navigation); starting another workout while one is active is impossible (plan-sync contract — the card shows resume, never a contradictory start).

## 4. Rebuilt flows (major tasks)

Notation: entry → decisions → screens → primary actions → feedback → error paths → exit → persistence. Only changes from the baseline are called out; unchanged mechanics are marked "preserved".

### 4.1 First use (new user, guest or account)
Entry: launch → Splash → Welcome. Decisions: account vs labeled guest path (NEW: guest labeled explicitly). Screens: the same 9 onboarding screens, in order, with copy fixes (goal/level explanations, injury optional-by-default preserved, plan offer Skip visually equal to Accept). NEW: summary screen before tabs restating choices (goal, level, days, diet, injuries) with an edit link to You → Training Preferences. Primary actions: Create account / Continue as guest / per-step Continue / Skip plan offer. Feedback: validation errors inline (password rule shown before submit, not only after failure). Error paths: validation, auth errors (neutral copy), network failure (retry, guest fallback preserved). Exit: tabs (Today, Simple mode default for new accounts). Persistence: profile to store on completion (preserved); onboarding state machine preserved (local state + `?screen=` override).

### 4.2 Returning user
Entry: launch → hydration splash → last tab restored (preserved) with one addition: on training days, Today shows the workout card as the resume/start affordance regardless of landing tab (persistent resume affordance during an active workout). Decisions: none required to reach today. Screens: Today (returning-user state when gap detected: "Welcome back — last session [date], plan [name]. Start light?" — presentation only, no new programming logic). Primary actions: resume/start, view history. Feedback: sync status visible in the Today header area (NEW: status text near the bell — synced/syncing/local-only, never color alone). Error paths: stale shell (flagged behavior fix D6, not redesigned around); sync failure → Settings → Data status + Sync now (preserved). Exit: any tab. Persistence: last tab, sync state (preserved).

### 4.3 Start or resume a workout
Entry: Today workout card, Train plan card, or persistent resume affordance. Decisions: which plan/day (plan-synced card decides; "Change workout" preserved). Screens: plan card → perform surface directly (NEW: no logger hop for starting); logger only when building/editing. Primary actions: Start / Resume / Change workout. Feedback: active-workout fullscreen with session start time; draft auto-save begins. Error paths: active workout already exists → resume shown, start suppressed (contract preserved); plan missing → empty state with create CTA. Exit: finish, discard (confirmed), pause-and-save-draft (preserved). Persistence: draft to localStorage (preserved).

### 4.4 Set logging (active workout)
Entry: perform surface, Beginner (Simple) or Advanced (Detailed) mode. Decisions: values per set; set options (RPE/RIR/type) via expander in Simple, open in Detailed. Screens: one perform surface (exercise → set → values → previous → next action). Primary actions: stepper weight/reps, complete set, next/prev exercise, rest timer (docked, never covering controls — NEW placement), finish, discard (confirmed). Feedback: set-complete transition (scale-in 200ms, state first, animation after); rest timer linear progress; previous performance labeled with scope ("Last session · [date]"). Error paths: wrong values → edit in place (no modal trip); keyboard must not obscure the current set (layout rule); interruption → draft restore with explicit "Draft restored" affordance (NEW visibility, same mechanism). Exit: finish → summary (below). Persistence: component state + draft auto-save until Finish (preserved).

### 4.5 Completing a workout
Entry: Finish in the perform surface. Decisions: none required (review is optional). Screens: summary FIRST (duration, exercises, sets, volume, genuine PRs — calculations untouched), then ONE optional "Coach's take" expansion (NEW: replaces the forced modal stack summary → take → review → debrief; the underlying modals' content is reachable from the expansion, not forced in sequence). Primary actions: Done (back to Today/Train), expand Coach's take. Feedback: "Saved" state stated in text (not color alone — D2 fix applies here). Error paths: finish computation fallback (duration from session start, preserved fallbacks); PR derivation single-source (verification item). Exit: Done → landing tab. Persistence: `addWorkout(entry)`, draft cleared (preserved).

### 4.6 Reviewing history and progress
Entry: Train → History, or Progress tab, or in-workout exercise-history expander (NEW). Decisions: session vs lift vs metric vs range. Screens: history modal detail (preserved); Progress sub-tabs with reconciled labels; spotlight chart + pinned override (NEW). Primary actions: open detail, switch sub-tab, set range/filter (persisted per chart — NEW persistence), pin spotlight. Feedback: chart titles stating the question, labeled axes + units, measured/estimated legend (NEW frame standard). Error paths: empty states as designed patterns (not bare conditionals — NEW shared EmptyState component); no data for a lift → explicit "no sessions yet" + first-action link. Exit: back to tab. Persistence: filters/ranges persisted (NEW); history derivation unchanged.

### 4.7 Recording and reviewing nutrition
Entry: Fuel tab, Today nutrition strip, Today quick actions. Decisions: scan vs manual vs barcode vs voice vs NL text (all preserved as inputs). Screens: scan (loading → review → save) / manual form / barcode / history (Meals segment) / macros breakdown. Primary actions: Scan Meal, Add Manually, quick-add pinned foods, edit entry, set goals. Feedback: per-item exact/estimated chips in scan review (NEW: chip per item, not banner-only); totals recalculated visibly on edit; portion-memory transparency ("your usual: …" label — NEW copy, same mechanism). Error paths: unmatched food → custom fields immediately (preserved, made prominent); scan failure → retry + manual fallback (preserved); duplicate submission guards per modal (preserved). Exit: back to Fuel/Today. Persistence: meals, targets, portion memory (preserved); scan chain + bridge mapping untouched; no offline-scan claim anywhere.

### 4.8 Changing preferences (theme, density, dashboard, training)
Entry: You → Settings → Appearance & Personalization (theme/density/dashboard) or Training Preferences (schedule/target/experience/units/language). Decisions: preset vs custom accent (with auto-correction preview); Simple vs Detailed; card visibility/order. Screens: Appearance & Personalization section + "Customize Today" sheet (NEW); Training Preferences section. Primary actions: pick preset / enter custom hex / toggle density / toggle + reorder cards / restore defaults (scoped resets: layout, theme, density separately). Feedback: immediate visual preview on theme pick; toast confirming scope of any reset. Error paths: failing custom contrast → auto-corrected shade shown with a note before applying (never silently accepted for text); invalid stored preferences → defaults merged (existing `DEFAULT_UI_PREFERENCES` merge pattern). Exit: back to You/Today. Persistence: uiPreferences via Zustand persist (localStorage-first) + sync payload where the field is synced (implementation must audit per-field coverage — do not promise sync for local-only fields).

### 4.9 Error recovery (offline, sync, crash, stale shell)
Entry: banner, status text, or error screen. Decisions: retry vs continue offline vs check status. Screens: offline banner + details modal (preserved), error/loading states (preserved), sync status in Today header (NEW visibility) + Settings §1 (preserved). Primary actions: Retry, Continue offline, Sync now, Dismiss. Feedback: plain-words status (synced/syncing/local-only + what syncs: 6 tables; local-only items named). Error paths: sync conflict → tombstone reconcile (preserved, no UI change to logic); multi-tab → tab-leader coordination (preserved); stale shell → flagged behavior fix D6 (versioned cache + update prompt) — NOT redesigned around. Exit: back to prior tab. Persistence: local-first store, sync queue (preserved).

### 4.10 Sign out / account switch / delete
Entry: You → Profile (log out) or Settings → Account & Security / Data & Privacy. Decisions: keep vs clear local data on sign-out (preserved choice); delete confirmation chain (preserved, multi-step). Screens: auth surfaces (unified method display — NEW presentation, same methods), sign-out confirm, delete-account flow (token-mailed, preserved). Primary actions: Sign out, Switch (sign out + sign in — no multi-account switcher exists, not added), Delete account. Feedback: neutral error copy; never "Supabase" in user copy. Error paths: OAuth URL hop is structurally mandatory on free tier (no code fix — custom domain is the user's separate decision). Exit: guest state or onboarding (preserved). Persistence: sign-out clear semantics preserved exactly; delete purge preserved exactly.

## 5. Today section architecture (the fold decision, made concrete)

| Order | Section | Simple (default, new users) | Detailed (default, existing users) | Hideable? | Notes |
|---|---|---|---|---|---|
| 1 | Header (bell, avatar) | Same | Same | No | Bell opens ReminderCenter; avatar opens You → Profile. Sync status text near bell (NEW). |
| 2 | Today's workout card | Same (start/resume, never contradictory) | Same | No — essential-action protection | Plan-sync contract preserved. |
| 3 | Nutrition strip | Calories + protein, tap → Fuel | Same + carbs/fat inline | Yes (but default on) | Totals must match Fuel exactly. |
| 4 | Coach section | One section: today's note + weekly-review summary; athlete facts behind expander | Same + athlete top-2 visible + review detail link | Yes | Consolidates PR #41's collapse further. Evidence-backed only. |
| 5 | Habit matrix | Today only (compact) | Full week Mon–Sun | Yes | Week = Mon–Sun always. |
| 6 | Quick actions | Same | Same | Yes | Labels identical to Fuel counterparts; same forms. |
| 7 | Hydration quick-add | Same | Same | Yes | Water + creatine (Fuel definitions). |

Steps slot reserved (no layout shift). Quote: Coach footer only, never a section. |

**Designed states:** Training day (workout card primary) · Rest day (explicit recovery state: no workout card pretending otherwise; habits + weekly summary) · Returning user (welcome-back state with last session + plan, no guilt copy) · New user (first-week empties: each empty section states its next action, not just "no data") · Active workout (persistent resume affordance; no contradictory start) · Offline (banner + local operation, same layout).
